### CB-02 · A comma-authored keywords value ships as one unsplit token on all four outputs; nothing re-delimits or gates it on the pre-upload path

*major* · outputs 01, 02, 03, 04 · verification confirmed · scope `concept`

**Columns.** keywords, digicards, related_concepts

**Required.** Contract §16 and Appendix B.1 (docs/…contract-v2.md:403-423, 1160): every exported multi-value cell uses exact ` \| `; `keywords`/`digicards`/`related_concepts` must be "Trimmed, ordered, no empty or duplicate tokens". §42 gate 3: "Pipe-delimited lists parse to the expected ordered identities with no empty/dangling token." Register Q26: comma/semicolon joins retired at every writer, reader and read-back, with a one-time db backfill re-delimiting stored legacy lists (plain lists split on the legacy comma).

**Actual.** Both writers deliberately refuse to split commas: writer._list_cell (writer.py:768-774) and assessment_workbook._bands_record (:725-732) call `split_multi(value, legacy_commas=False)`, which per bulk_import/__init__.py:223-242 returns a pipe-free value as exactly one token. The re-delimiting therefore lives entirely in the startup DB backfill (db.py:312-339), which iterates persisted `models.Concept` rows. Outputs 01/03 before the DB upload, and the Master snapshot in every case, are built from TRANSIENT concepts constructed straight from the staged release record (build_concepts_release_files.py:770-803, `keywords=str(record.get('keywords') or '')`) — those rows never pass through the backfill. The delimiter is instructed only in the legacy skeleton prompt (generation.py:1103 "3-6 lowercase terms separated by ' \| '"); the Phase-3 prompt surface (phase3/prompts.py:31,227,461,582,624) names `keywords` with no delimiter rule, and the refiner is free to rewrite it (prompts.py:630-633). No validator on any of the four outputs checks the delimiter or the token shape. Measured: a snapshot carrying keywords 'k1, k2' rendered through render_master_file and read back as the single cell value 'k1, k2'.

**Remedy proposed.** State the ` \| ` rule in the Phase-3 authoring and refiner prompts that touch `keywords`, and add a mechanical read-back assertion (a token-shape check next to `list_token_defects`) that runs on every concept-band row of all four outputs, so a comma-joined cell is a named defect rather than a silent one-token list. Do not add a comma-splitting heuristic at the writer — that would guess whether a comma is content.

## 6 · Method

Twelve audit passes ran independently, each given the governing documents in
precedence order and the code map, and each required to cite the rule, locate
the writing code, state the actual behaviour with a file and line, and reach a
verdict. Several passes rendered real workbooks from a scratch database rather
than reading code alone.

Each finding was then attacked twice. One verifier re-read the cited rule in
full and tried to show it had been misread or superseded; the other read the
cited code and tried to show it already complies. A finding survived only when
neither succeeded, and a single dissent is recorded with the finding as
contested.

No repository file was modified by the audit. The findings propose remedies;
none is applied here.
